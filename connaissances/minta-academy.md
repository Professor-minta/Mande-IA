## Les supports de cours, réservés aux élèves inscrits
Les élèves de la formation tech reçoivent 10 supports de cours, qui ne sont pas publics :
1. Méthode de travail et sécurité : organiser son dossier de travail, les mots de passe, la double authentification, les clés SSH, les 5 règles absolues, reconnaître une arnaque.
2. Git et GitHub : installer Git, les 4 commandes de tous les jours, le fichier .gitignore, sécuriser son compte GitHub, envoyer un projet, branches et Pull Requests, réparer une erreur.
3. Domaines et DNS : choisir un bon nom, acheter le domaine, les enregistrements DNS, relier le domaine au serveur, vérifier que ça marche.
4. Ton serveur VPS sur DigitalOcean : créer le Droplet, première connexion, créer son utilisateur, le pare-feu, interdire la connexion par mot de passe, les mises à jour de sécurité automatiques, la surveillance et les sauvegardes.
5. aaPanel, sites web et HTTPS : installer et sécuriser aaPanel, installer le serveur web, mettre un site en ligne, le HTTPS avec Let's Encrypt.
6. Node.js, de ton ordinateur au serveur : un projet propre, le serveur, GitHub, le déploiement avec aaPanel et la mise à jour de l'application.
7. Python et automatisation : un environnement par projet, les bases, trois scripts (sauvegarder un dossier, vérifier que des sites répondent, calculer des totaux dans un CSV), lancer un script tout seul sur le serveur.
8. IA locale avec Ollama et Mande-IA v3 : installer Ollama, lancer `ollama run professor-minta/mande-ia.v3`, les commandes Ollama, l'API sur http://localhost:11434, créer son propre assistant avec un Modelfile. Le modèle pèse environ 2 Go ; 8 Go de mémoire au minimum, 16 Go conseillés.
9. Open WebUI, une IA hors ligne pour toute l'équipe : installer Open WebUI (Python 3.11 ou 3.12), l'ouvrir sur http://localhost:8080, travailler sans internet, utiliser ses documents, toute l'équipe sur le même réseau, la version Docker pour un serveur.
10. Construire et présenter ton projet : choisir un vrai problème du Mali, planifier, la liste de sécurité, présenter en 5 minutes.

## Les 5 règles absolues
1. Les clés et mots de passe ne vont jamais dans un message, ni WhatsApp, ni e-mail, ni chat avec une IA.
2. Les fichiers .env ne vont jamais sur GitHub : on les ajoute au fichier .gitignore.
3. On recadre les captures d'écran avant de les partager : pas d'adresse IP, pas de port de panneau, pas de lien de session, pas de clé.
4. Une clé exposée est une clé perdue : on la remplace tout de suite.
5. On sauvegarde avant de modifier : un instantané du serveur ou une copie du fichier.

## Le projet final
Le projet doit contenir : un dépôt GitHub propre avec un README et sans aucun secret ; une adresse en ligne en HTTPS ; une partie serveur en Node.js ou en Python ; une partie automatique (tâche Cron) ou intelligente (IA locale) ; une sauvegarde. Il est noté sur 20 : vrai problème clairement expliqué (4 points), fonctionne en ligne en HTTPS (4), partie serveur et partie automatique ou IA (4), sécurité (3), code et README propres (3), présentation claire dans le temps (2). L'élève qui n'a pas pris de domaine ni de serveur présente son projet sur son ordinateur et explique comment il le mettrait en ligne.

## Aider un élève bloqué
- Demander le numéro de la séance, l'étape et le message d'erreur exact, recopié en texte. Ne jamais demander de clé, de mot de passe ni de capture qui montre une adresse IP.
- « Already up to date » après git pull : la Pull Request n'est pas encore fusionnée sur GitHub.
- Une modification ne s'affiche pas : redémarrer le projet Node dans aaPanel, puis recharger la page avec Ctrl+F5.
- Un domaine qui ne répond pas : vérifier l'enregistrement A, puis attendre la propagation du DNS, souvent moins d'une heure.
- Un site injoignable : vérifier le pare-feu du serveur et celui d'aaPanel pour le port concerné.
- Coller une commande : copier seulement la commande, jamais le texte d'explication autour.
